# Игропоиск — обязательные правила

## Абсолютный запрет пустых страниц

Публикация пустой, частично заполненной, временной или «догружающейся» страницы игры запрещена. Игра не появляется на главной, в каталоге, поиске, подборках, sitemap или по публичному маршруту, пока не прошла publish gate.

Запрещены фразы «информация загружается», «материалы пока не найдены», пустые вкладки, фиктивные карточки и подставные тексты. Неполные записи существуют только во внутренней очереди со статусом `draft`, `collecting`, `review` или `rejected`.

## Publish gate

Статус `published` разрешён только при одновременном выполнении требований:

1. Идентичность подтверждена официальным источником и крупной базой либо двумя независимыми базами.
2. Проанализировано 10–20 реальных источников.
3. Использованы доступные официальные страницы игры, разработчика и издателя.
4. Заполнены название, дата/статус релиза, жанры, платформы, разработчик и издатель.
5. Есть краткое описание и отдельный интегрированный обзор.
6. Есть сюжет, структура кампании либо объяснение отсутствия сюжетной кампании.
7. Есть минимум 4 содержательные особенности.
8. Есть hero, обложка и минимум 6 реальных скриншотов.
9. Есть минимум одно официальное видео, если оно существует.
10. Рассчитан рейтинг Игропоиска либо зафиксирована недостаточность данных.
11. Каждая публичная вкладка содержит реальные материалы; пустая вкладка не создаётся.
12. Для текста сохранены URL, название источника, дата публикации, дата проверки и доверие.
13. Автоматическая проверка полноты завершилась без ошибок.
14. Запись прошла редакционную или формальную автоматическую проверку качества.

Если хотя бы одно условие не выполнено, страница не публикуется вообще.

## Рейтинги

На сайте только два рейтинга:

- рейтинг Игропоиска по шкале 0–10;
- рейтинг пользователей Игропоиска.

Отдельного рейтинга «критики» нет. Пользовательский рейтинг полностью скрывается, пока нет ни одного голоса. Ноль и пустая карточка запрещены.

## Страница игры

Hero — слайдер из официального key art/header и 4–6 реальных скриншотов. Фон переключается автоматически примерно раз в 5–6 секунд и вручную.

Возможные вкладки: «Всё об игре», «Медиа», «Статьи», «Обзоры», «Гайды», «Советы», «Новости». Вкладка создаётся только при наличии содержимого.

«Всё об игре» обязательно содержит описание, интегрированный текст, сюжет/структуру кампании, особенности, дату выхода, жанры, платформы, разработчика, издателя, скриншоты и раскрываемый список источников.

«Медиа» содержит отдельные блоки скриншотов и официальных видео.

## Фреймворк 10–20 источников

Собственный текст Игропоиска не является пересказом одного сайта. Для каждой страницы или статьи анализируются 10–20 источников.

Приоритет:

1. официальный сайт игры;
2. сайт разработчика;
3. сайт издателя;
4. Steam, PlayStation, Xbox, Nintendo, Epic Games Store, GOG;
5. IGDB, RAWG, Metacritic, OpenCritic;
6. IGN, GameSpot, PC Gamer, Eurogamer, Rock Paper Shotgun, GamesRadar+, Polygon;
7. Игромания, StopGame, GameMAG и проверяемые редакционные материалы DTF.

Официальные источники имеют приоритет для дат, платформ, компаний и состава изданий. Оценочные суждения подтверждаются несколькими независимыми публикациями. Чужие статьи не копируются. Для каждого факта сохраняются доказательства источника.

## Структура данных

Каждая игра содержит блоки `publication`, `identity`, `release`, `companies`, `classification`, `editorial`, `media`, `ratings`, `materials`, `sources`.

Публичный JSON содержит только записи со статусом `published` и `gate_passed: true`. Фронтенд повторно проверяет publish gate. Сборка завершается ошибкой при обнаружении хотя бы одной неполной публичной записи.

## Единый контракт ширины

Внешняя ширина контента всех публичных страниц, секций и блоков определяется только файлами `assets/layout-contract.css` и `assets/layout-contract.js`. Главная, поиск, новости, «Во что поиграть?», календарь релизов, страницы игр, статьи, обзоры, шапки и внутреннее содержимое полноширинных секций обязаны использовать один и тот же адаптивный контейнер и одинаковые боковые поля.

Полноширинным может быть только фон, изображение или декоративная оболочка секции. Содержимое внутри такой секции всё равно обязано находиться в общем контейнере. Локальные `width`, `max-width`, отрицательные поля, viewport-ширина и отдельные контейнерные переменные не могут изменять внешний контентный фрейм. Они разрешены только для внутренних колонок, текста, карточек и медиа внутри общего контейнера.

Любое отклонение ширины запрещено без отдельной прямой разрешительной команды пользователя. Технически исключение допускается только через атрибут `data-ig-width-exception="TOKEN"` и одновременно зарегистрированную запись с путём, причиной и автором разрешения в `config/layout-width-exceptions.json`. Незарегистрированное, неиспользуемое или неполное исключение блокирует публикацию.

Перед каждой публикацией `scripts/enforce_layout_contract.py` обязан внедрить контракт последним во все HTML-файлы и повторно проверить их. GitHub Pages не разворачивает сайт при отсутствии контракта, попытке переопределить его системные переменные или наличии неразрешённого исключения.

## Единая архитектура страниц

Сайт имеет одну дизайн-систему и один внешний каркас. Отдельная страница или сервис не может создавать собственную мини-дизайн-систему. Страница встраивает свои функциональные блоки внутрь общей шапки, общего фона, общего контейнера, общих колонок, типографики, поверхностей, радиусов и интерактивных состояний.

Файлы конкретной страницы могут управлять только внутренней компоновкой её блоков. Им запрещено переопределять `body`, `.site-header`, `.site-header__inner`, `.ig-container`, системные gutters, максимальную ширину страницы и горизонтальные поля внешнего фрейма. Отдельные классы шапки, отдельный фон всего документа и отдельная палитра hover-состояний запрещены.

Основные раскладки строятся из системных переменных `--ig-grid-left`, гибкой центральной колонки, `--ig-grid-right` и `--ig-grid-gap`. «Во что поиграть?» и календарь релизов подчиняются этой же архитектуре. На мобильном экране меняется только количество внутренних колонок; общий gutter сохраняется.

Системные hover-состояния определяются в `assets/site-system.css`. Базовый hover текста и навигации использует зелёный `--ig-rating`; локальная страница не создаёт собственный цвет hover. Publish gate блокирует отдельную шапку календаря, изменение шапки из CSS «Во что поиграть?» и попытку локально изменить внешний контентный фрейм.

## Единое меню сайта

Все публичные страницы используют общий компонент `assets/site-header.css` и `assets/site-header.js`, но эталоном является существующая шапка главной страницы. Компонент обязан воспроизводить её без редизайна: та же HTML-структура, те же классы, логотип, типографика, расстояния, пункты «Главное», «Во что поиграть?», «Поиск игр», «Календарь релизов», «Новости», кнопка поиска и переключатель темы.

Нативную шапку главной страницы запрещено заменять или перерабатывать. На других страницах общий компонент создаёт точную копию этой шапки. Единственное разрешённое визуальное изменение — полупрозрачный фон шапки с размытием содержимого под ней.

Запрещено добавлять без прямого разрешения новые плашки, рамки вокруг навигации, декоративные знаки у логотипа, дополнительные контекстные кнопки, новое мобильное меню или любое иное отличие от шапки главной страницы. На узком экране применяется существующее поведение главной страницы.

Publish gate внедряет общий CSS и JavaScript меню во все HTML-файлы. Если шапка отсутствует, создаётся точная копия главной. Отдельные локальные варианты шапки запрещены.

## Развитие проекта

Существующий каркас улучшается, а не заменяется новым прототипом. Маршруты, вкладки, модель данных, два рейтинга и publish gate являются постоянной основой проекта.
