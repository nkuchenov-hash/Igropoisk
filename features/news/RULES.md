# Модуль новостей

## Граница модуля

Интерфейс новостей находится только в `features/news/`.

- `home-widget/` отвечает только за новостной блок главной.
- `archive-page/` отвечает только за страницу списка новостей, поиск и фильтры.
- `content-api/` — единственная точка чтения, нормализации, объединения и ранжирования новостных данных.
- `admin-health/` — только read-only представление состояния pipeline для администратора.
- `shared/` отвечает только за общий интерфейс представления: подписи, теги, HTML карточек и совместимый фасад для экранов.
- `styles/` содержит только композицию и селекторы, начинающиеся с `.ig-news`.

`home-widget/`, `archive-page/` и `shared/` не знают имён конкретных JSON-файлов и не выполняют `fetch` новостных данных. Они работают только через глобальный контракт `window.IgropoiskNewsContent`.

## News Content API

Публичный контракт версии 1:

- `getAll({ lang, force })` — единый нормализованный набор новостей;
- `getHome({ lang, region, globalLimit, regionalLimit, force })` — подборка для главной;
- `health()` — состояние подключённых источников контента;
- `invalidate()` — очистка внутреннего кэша;
- вспомогательные методы чтения региона, оценки и проверки записи.

Текущий backend API читает существующие JSON в репозитории. Позже backend можно заменить базой данных или сетевым сервисом, не меняя код карточек, главной и архива. Изменение публичного контракта требует новой версии API и отдельной миграции потребителей.

API работает только на чтение. Он не записывает данные, не запускает парсеры и не изменяет HTML, CSS или другие разделы сайта.

## Автономный pipeline

Единственный автоматический путь публикации новостей:

1. `.github/workflows/news-pipeline.yml` запускается каждый час.
2. `scripts/run-news-pipeline.mjs` определяет, какие группы источников действительно пора обновить.
3. Глобальные медиа обновляются раз в сутки; официальные источники и YouTube-сигналы — раз в час.
4. После любого обновления заново строятся `data/news-events.json` и `data/news-home-ru.json`.
5. `scripts/build-news-pipeline-health.mjs` формирует `data/news-pipeline-health.json`: время последнего успешного запуска, объёмы и возраст данных, изображения, успешность источников и последовательные ошибки.
6. `scripts/validate-news-pipeline.mjs` проверяет объём лент, URL, даты, изображения, русский фид главной, свежесть, здоровье официальных источников и отсутствие катастрофического сокращения данных.
7. News Content API, границы модуля и центральные компоненты проверяются до публикации.
8. Все JSON, health snapshot и изображения публикуются одним проверенным commit. При ошибке commit не создаётся, а уже опубликованные данные остаются рабочими.
9. После успешного GitHub Pages deploy выполняется browser smoke опубликованной главной, архива и read-only health-страницы.

Конфигурация cadence, стадий, health thresholds и разрешённых output-путей находится только в `config/news-pipeline.json`. Старые workflows `update-news.yml` и `update-publisher-news.yml` не имеют собственных расписаний и являются только ручными алиасами единого pipeline.

Pipeline не редактирует HTML, CSS, JavaScript интерфейса, игры, обзоры, релизы, календарь, авторизацию или шапку. Добавление нового источника не должно требовать изменения экранов новостей.

## Health и админка

`data/news-pipeline-health.json` — канонический снимок состояния последнего успешно подготовленного новостного snapshot. Он хранит только операционные метрики и безопасную диагностику без секретов и управляющих токенов.

`admin/news-health/` и `features/news/admin-health/` работают только на чтение. Экран требует роль `admin`, загружает health snapshot с `cache: no-store` и не имеет форм, API записи, кнопок редактирования или прямого запуска pipeline.

Источник считается систематически неработающим после числа последовательных ошибок, заданного в `config/news-pipeline.json`. Успешная проверка сбрасывает счётчик. Статус `degraded` не блокирует публикацию, а `error` блокирует commit.

## Центральные компоненты

Модуль не владеет ни одним визуальным компонентом. Карточки, кнопки, поля поиска, фильтры, теги, заголовки и состояния берутся только из `assets/design-system.css` через классы `ig-*`.

В `features/news/styles/` запрещены цвета, фоны, границы, радиусы, тени, шрифты, размеры текста, визуальные состояния и любые собственные варианты компонентов. Разрешены только сетка, размеры областей, размещение, прокрутка и адаптивная композиция.

Префикс `.ig-news` обозначает только принадлежность композиции к модулю и не даёт права создавать локальный визуальный компонент.

## Запрещено

При задаче на внешний вид или функции новостей нельзя изменять шапку, общую сетку, авторизацию, игры, обзоры, релизы, календарь и их данные. Нельзя добавлять глобальные CSS-селекторы в стили модуля. Нельзя создавать локальную кнопку, карточку, поле, тег или панель даже под префиксом `.ig-news`.

Нельзя обращаться к новостным JSON напрямую из публичных экранов, дублировать нормализацию в UI, сохранять состояние новостей в `localStorage` или добавлять обходной источник данных вне `content-api/`.

Нельзя создавать второй scheduled workflow, который самостоятельно пишет `data/news*.json`, `data/publisher-news.json`, `data/news-pipeline-health.json`, `assets/news/` или `assets/publisher-news/`. Ручные запуски также обязаны идти через `.github/workflows/news-pipeline.yml`.

Административному health-экрану запрещено менять JSON, отправлять POST/PUT/PATCH/DELETE, запускать workflow или хранить собственное состояние pipeline.

## Данные

News Content API читает структурированные публикационные данные:

- `data/news-events.json`
- `data/news.json`
- `data/publisher-news.json`
- `data/news-home-ru.json`
- `assets/news/`
- `assets/publisher-news/`

Pipeline дополнительно хранит вспомогательные официальные видеосигналы в `data/youtube-signals.json` и операционный snapshot в `data/news-pipeline-health.json`.

Изменение интерфейса или API не должно переписывать эти файлы. Парсеры не должны редактировать HTML, CSS или JavaScript модуля.

## Ветки

- `news-ui/*` — разрешены изменения только в `features/news/`, но новые компоненты требуют отдельного согласованного изменения центральной дизайн-системы.
- `news-content/*` — разрешены только новостные JSON и изображения.
- изменения pipeline, health и парсеров выполняются отдельной задачей и отдельной веткой.

## Хронологический архив

- Архив группируется по стабильному полю `publishedDay` в обратном хронологическом порядке.
- Внутри дня новости сортируются по точному `publishedAt`, от новых к старым.
- Канонический URL источника может присутствовать в ленте только один раз.
- В русских заголовках дней текущий год не показывается; при переходе на другой год год указывается явно.
- Постоянный URL фильтра по игре: `?page=news&game=<slug>`.
- Тег игры становится ссылкой только при существовании `game/<slug>/index.html`; кандидат без страницы не получает публичную ссылку.

## Идентификация игр

Автоматическая связь разрешена по точному каноническому названию, настроенному альтернативному названию, сокращению, однозначной серии, внешнему ID или сохранённому ручному решению. Совпадение одного обычного слова недостаточно.

- `data/news-game-aliases.json` хранит альтернативные названия, сокращения, серии и внешние ID.
- `data/news-game-overrides.json` хранит долговременные ручные решения по стабильному ID новости или каноническому URL.
- `data/news-game-review.json` формируется pipeline для неоднозначных совпадений и отсутствующих игровых страниц.

Неоднозначное совпадение не создаёт публичную ссылку. В админке парсера новостей разрешён локальный черновик ручных решений и экспорт replacement-файла `data/news-game-overrides.json`; после добавления в репозиторий решения повторно применяются каждым запуском pipeline.

## Время публикации и дубликаты

`publishedAt` хранит точный ISO-момент. Стадия нормализации также сохраняет `publishedDay`, `publishedLocalTime` и редакционную временную зону, чтобы календарный день не зависел от временной зоны браузера посетителя. Перед дедупликацией и расчётом event ID URL очищается от fragment и tracking-параметров.

Порядок pipeline для этих данных:

1. сборщики формируют исходные ranked и official записи;
2. `scripts/normalize-news-records.mjs` канонизирует URL, удаляет дубли, фиксирует календарный день и связывает игры;
3. `scripts/build-news-events.mjs` объединяет публикации об одном событии, повторно применяет ручные решения и формирует очередь проверки;
4. существующие сборка главной, health, validation и immutable publication продолжают работать без изменения соседних модулей.

Обязательные проверки: `node scripts/test-news-archive.mjs`, `node scripts/test-news-game-linker.mjs` и существующие тесты pipeline, Content API и границ модуля.
