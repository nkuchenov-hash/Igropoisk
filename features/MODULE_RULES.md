# Правила функциональных модулей Игропоиска

## Регистрация

Каждый каталог верхнего уровня в `features/` обязан быть зарегистрирован в `config/feature-modules.json`. Режим по умолчанию для нового модуля — только `strict`.

Строгий модуль обязан иметь:

- `module.json` с идентификатором модуля и `enforcement: "strict"`;
- `RULES.md` с границами ответственности;
- перечень используемых центральных компонентов `centralComponents`;
- ссылку на `assets/design-system.css` как единственный источник визуальных компонентов.

## Компоненты

Модуль не создаёт собственные кнопки, карточки, поля, теги, панели, модальные окна, состояния или типографические компоненты. Он использует только классы из `config/design-system-components.json`.

Локальный CSS управляет только композицией: сеткой, порядком, размерами областей, размещением, прокруткой и адаптивным расположением. Цвета, фоны, границы, радиусы, тени, шрифты, визуальные состояния, анимации компонентов и локальные `--ig-*` токены запрещены. Допускаются только технические переменные с префиксом конкретного модуля, например `--ig-news-*`.

## Существующие служебные каталоги

`content-pipeline`, `home-releases` и `reviews-of-day` зарегистрированы как исторические `metadata-only` каталоги. Они могут содержать только правила, документацию и данные. Добавление в них HTML, CSS или исполняемого JavaScript запрещено до отдельного перевода каталога в строгий модуль.

## Миграция старых разделов

Существующие страницы не переделываются массово. При отдельной согласованной работе над разделом его новые компоненты сначала добавляются в центральную дизайн-систему, а локальные компоненты заменяются постепенно, без изменений соседних страниц и поведения.
