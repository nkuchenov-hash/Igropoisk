# Редакционный календарь релизов

## Граница данных

`data/releases/current.json` — сырой результат обнаружения. Он не является публичным API.

`data/release-candidates/current.json` — внутренняя база кандидатов со статусом, источниками, сигналами значимости и причинами решения.

`data/release-candidates/editorial.json` — ручные редакционные решения. Парсер и материализатор этот файл не записывают. Именно здесь фиксируются публикация, запрет, причина отклонения, тип релиза, исправления даты/платформ и заблокированные поля.

`data/releases/public.json` — единственный источник публичного календаря.

## Реально подключённые источники

- Steam coming-soon и Steam appdetails: автоматическое обнаружение **только PC-релизов**.
- RAWG: необязательное вспомогательное обогащение при наличии `RAWG_API_KEY`; не подтверждает дату самостоятельно.
- Официальные магазины платформ, сайты издателей/разработчиков и официальные анонсы: поддерживаются через проверяемый реестр `config/release-official-claims.json`. Каждая запись хранит URL, платформу, регион, дату/период и уверенность.
- IGDB: предусмотрен как вспомогательный тип источника для обнаружения/сверки, но автоматический IGDB-клиент в этой ветке не подключён и IGDB никогда не считается единственным подтверждением.

## Допуск в публичный календарь

Запись должна иметь надёжно подтверждённое платформенное событие и сигнал общественного/редакционного интереса: независимую публикацию, страницу Игропоиска, заметного разработчика/издателя, официальный анонс, прохождение фильтра значимости главной или ручное одобрение.

Demo, prologue, playtest, soundtrack, косметика, технические приложения, мелкие DLC и дубли изданий исключаются автоматически. Полноценное дополнение публикуется с типом `expansion`.

Точная консольная дата допускается только при официальном источнике для конкретной консоли. Steam не может подтвердить PlayStation, Xbox или Nintendo.

## Ручная редактура

Админка сохраняет рабочую копию решений в браузере и экспортирует целиком канонический `editorial.json`. После проверки файл помещается в `data/release-candidates/editorial.json`. Следующий запуск парсера применяет его поверх сырых данных и не перезаписывает.

## Проверки

```bash
node scripts/test-release-calendar-policy.mjs
node scripts/materialize-release-calendar.mjs
node scripts/validate-release-calendar.mjs
```

Проверка падает, если публично появился исключённый тип, дубль, неподтверждённая платформа, Steam-дата консоли, снятый ручной запрет или более 12 релизов в один день.
