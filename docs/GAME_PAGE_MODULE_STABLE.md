# Игропоиск — стабильный модуль создания страниц игр

**Статус:** READY / STABLE  
**Зафиксировано:** 2026-09-02  
**Уточнение границ:** 2026-09-02

## Назначение

Модуль создания страниц игр отвечает за обнаружение/идентификацию игры, сбор и хранение фактов, медиа и связанных данных, проверку качества страницы, сборку общего шаблона и публикацию страницы.

**Обзор игры не является частью модуля страницы игры.** Это отдельный контентный материал/подсистема, который страница умеет подключать и показывать, когда он существует. В будущем обзоры могут быть оформлены как самостоятельный модуль без изменения модуля страниц.

## Что входит в модуль страницы игры

- регистрация игры в Game Registry и разрешение её идентичности;
- сбор фактических данных об игре;
- сбор обложки, hero-арта, скриншотов, видео и других медиа;
- системные требования, платформы, разработчики, издатели, жанры, релизы и официальные ссылки;
- связи с другими играми и данные для блока похожих игр;
- хранение канонических данных страницы;
- quality control самой страницы и её медиа;
- сборка `game/<slug>/index.html` через единый общий шаблон;
- публикация и последующее обновление страницы;
- подключение связанных материалов из других модулей: обзоров, новостей, гайдов и т. п.

## Что НЕ входит в модуль страницы игры

- поиск профессиональных рецензий для написания редакционного обзора;
- построение корпуса рецензий;
- написание редакционного обзора Игропоиска;
- quality control текста обзора;
- жизненный цикл обзора как самостоятельной публикации.

Эти функции принадлежат review/editorial-подсистеме. Общий системный оркестратор может запускать оба конвейера рядом, но это не делает review-подсистему частью модуля страницы.

## Контракт интеграции с обзорами

- Страница игры может и должна иметь место для редакционного обзора Игропоиска.
- Если обзор уже опубликован, страница подключает его и показывает в соответствующем блоке.
- Отсутствие обзора **не блокирует создание или публикацию самой страницы игры**.
- Обзор обязан ссылаться на ту же каноническую игру через Game Registry/game_id.
- Оценка и другие данные, которые поставляет review/scoring-подсистема, подключаются как внешние связанные данные и не рассчитываются модулем страницы самостоятельно.
- Будущий отдельный модуль «Обзоры игр» должен иметь возможность создавать, обновлять и публиковать обзоры независимо от жизненного цикла страниц игр.

## Стабильный контракт страницы

- Страница создаётся через общий механизм и общий шаблон, а не отдельной ручной реализацией для конкретной игры.
- Основные факты и медиа проходят через канонические структуры данных.
- Ссылки и сущности игры, создаваемые другими модулями (новости, Popular, релизы и т. д.), используют существующий Game Registry и страницу, а не создают параллельную модель игры.
- Визуальная структура страницы регулируется `docs/game-page-design-system.md`.
- Архитектура идентификации игр и registry регулируется `docs/game-registry-architecture.md`.

## Freeze rule

Изменения создания/обогащения/рендера страницы игры, её page-QC или Game Registry считаются изменениями стабильного модуля страницы.

Изменения поиска рецензий, генерации обзора и review-QC считаются изменениями review/editorial-подсистемы и не должны автоматически считаться изменениями стабильного модуля страницы.

Запрещено без отдельной задачи на изменение самого модуля страницы:

- отключать или обходить существующий pipeline создания страниц;
- заменять реальные факты/медиа заглушками или синтетическими данными;
- создавать второй независимый механизм страниц игр;
- делать наличие редакционного обзора обязательным техническим условием публикации страницы;
- ломать связи news / Popular / releases → Game Registry → game page;
- вводить game-specific шаблоны или стили вместо общей системы.

## Правило для будущих PR

Если PR не посвящён непосредственно модулю страниц игр, изменения этого модуля должны быть минимальными и обратно совместимыми. Review/editorial-функции могут развиваться самостоятельно при сохранении интеграционного контракта через канонический game_id и связанные материалы.

Этот документ является guardrail: **стабильный модуль создания страниц игр не рефакторится и не переписывается попутно, а обзор остаётся отдельным подключаемым модулем/материалом.**
