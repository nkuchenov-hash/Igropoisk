# Игропоиск — стабильный модуль создания страниц игр

**Статус:** READY / STABLE  
**Зафиксировано:** 2026-09-02

## Назначение

Модуль создания страниц игр считается завершённым базовым модулем проекта. Его рабочее поведение является контрактом, который нельзя случайно менять при разработке новостей, релизов, поиска, главной страницы и других независимых частей Игропоиска.

## Стабильный контракт

- Страница игры создаётся через общий механизм и общий шаблон, а не отдельной ручной реализацией для конкретной игры.
- Основные факты игры, медиа, источники, обзоры и связанные данные должны проходить через существующий pipeline и канонические структуры данных.
- Для нормальной известной игры страница должна включать редакционный обзор Игропоиска, сформированный на основании реальных внешних обзоров/источников.
- Внешние обзоры допускаются только при наличии реально найденной публикации и ссылки на оригинал.
- Итоговая редакционная оценка не должна конфликтовать с отдельной независимой оценкой страницы: каноническая оценка формируется по принятой review/scoring логике.
- Ссылки и сущности игры, создаваемые другими модулями (например, новости, Popular, релизы), должны использовать существующую страницу/registry и не создавать параллельную несовместимую модель страницы.
- Визуальная структура страницы регулируется `docs/game-page-design-system.md`.
- Архитектура идентификации игр и registry регулируется `docs/game-registry-architecture.md`.

## Freeze rule

Любое изменение кода, которое затрагивает создание/обогащение/рендер страницы игры, сбор источников обзоров, формирование редакционного обзора, расчёт канонической оценки или Game Registry, должно рассматриваться как изменение стабильного модуля.

Такое изменение нельзя вносить как побочный эффект работы над другим модулем. Перед merge необходимо подтвердить, что существующий контракт страницы игры не регрессировал.

Запрещено без отдельной задачи на изменение самого модуля:

- отключать или обходить существующий pipeline создания страниц;
- заменять реальные источники заглушками или синтетическими данными;
- создавать второй независимый механизм страниц игр;
- менять каноническую модель оценок;
- удалять обязательный редакционный обзор для игр, для которых доступны достаточные источники;
- ломать связи news / Popular / releases → Game Registry → game page;
- вводить game-specific шаблоны или стили вместо общей системы.

## Правило для будущих PR

Если PR не посвящён непосредственно модулю страниц игр, изменения этого модуля должны быть минимальными и обратно совместимыми. При необходимости существенного изменения оно выносится в отдельный PR с явным описанием причины и проверкой регрессий.

Этот документ является guardrail: **стабильный модуль создания страниц игр не рефакторится и не переписывается попутно.**
