# Игропоиск — стабильный модуль создания страниц игр

**Статус:** READY / STABLE  
**Зафиксировано:** 2026-09-02  
**Уточнение границ:** 2026-09-04

## Назначение

Модуль создания страниц игр отвечает за обнаружение/идентификацию игры, сбор и хранение фактов, полного корпуса источников, медиа и связанных данных, проверку качества страницы, сборку общего шаблона и публикацию страницы.

**Обзор игры не является частью модуля страницы игры.** Это отдельный редакционный материал/подсистема. Но **полный корпус источников об игре является частью страницы игры и её базы данных**. Он существует независимо от того, написан ли собственный обзор Игропоиска.

## Что входит в модуль страницы игры

- регистрация игры в Game Registry и разрешение её идентичности;
- сбор фактических данных об игре;
- полный канонический корпус источников об игре: официальные страницы, магазины, базы, профессиональные рецензии, прямые ссылки на материалы, известные оценки и медиа-источники;
- хранение для каждого источника его URL, публикации/названия, назначения, доступной оценки и даты проверки;
- использование единого корпуса источников для проверки фактов, кратких описаний, Game DNA, медиа, similarity и рейтингов;
- публичная вкладка «Источники», позволяющая открыть оригинальные материалы даже если собственного обзора Игропоиска ещё нет;
- сбор обложки, hero-арта, скриншотов, видео и других медиа;
- системные требования, платформы, разработчики, издатели, жанры, релизы и официальные ссылки;
- связи с другими играми и данные для блока похожих игр;
- хранение канонических данных страницы;
- quality control самой страницы, её источников и медиа;
- сборка `game/<slug>/index.html` через единый общий шаблон;
- публикация и последующее обновление страницы;
- подключение связанных материалов из других модулей: обзоров, новостей, гайдов и т. п.

Канонический источник-корпус хранится в `data/game-sources/<slug>.json`. Он принадлежит game-page-модулю и предназначен для повторного использования другими подсистемами, а не для повторного независимого поиска одних и тех же материалов.

## Что НЕ входит в модуль страницы игры

- написание редакционного обзора Игропоиска;
- синтез текста обзора из корпуса источников;
- quality control текста обзора;
- жизненный цикл обзора как самостоятельной публикации.

Важно: **поиск и хранение профессиональных рецензий как источников об игре входит в модуль страницы.** Не входит только создание собственного редакционного обзора Игропоиска на их основе.

## Контракт интеграции с обзорами и рейтингом

- Страница игры может и должна иметь место для редакционного обзора Игропоиска.
- Если обзор уже опубликован, страница подключает его и показывает в соответствующем блоке.
- Отсутствие обзора **не блокирует создание или публикацию самой страницы игры**.
- Даже без собственного обзора пользователь должен иметь доступ к полному списку найденных внешних материалов во вкладке «Источники».
- Review/editorial-подсистема обязана использовать канонический `data/game-sources/<slug>.json` как исходный корпус, а не создавать параллельную базу источников.
- Scoring-подсистема использует все найденные в этом корпусе подтверждённые профессиональные оценки; рассчитанная оценка может отображаться на странице независимо от наличия собственного обзора.
- Обзор обязан ссылаться на ту же каноническую игру через Game Registry/game_id.
- Будущий отдельный модуль «Обзоры игр» должен иметь возможность создавать, обновлять и публиковать обзоры независимо от жизненного цикла страниц игр, используя уже собранную базу источников страницы.

## Стабильный контракт страницы

- Страница создаётся через общий механизм и общий шаблон, а не отдельной ручной реализацией для конкретной игры.
- Основные факты, источники и медиа проходят через канонические структуры данных.
- Источник-корпус — единая база доказательств об игре. DNA, рейтинг, медиа-исследование, краткие описания и будущий обзор должны ссылаться на неё, а не создавать несовместимые наборы источников.
- Ссылки и сущности игры, создаваемые другими модулями (новости, Popular, релизы и т. д.), используют существующий Game Registry и страницу, а не создают параллельную модель игры.
- Визуальная структура страницы регулируется `docs/game-page-design-system.md`.
- Архитектура идентификации игр и registry регулируется `docs/game-registry-architecture.md`.

## Approved / Working

Модуль страницы игры существует в двух состояниях, но остаётся **одним и тем же модулем**.

### Approved

- `main` — утверждённая production-версия Game Page Module.
- Все опубликованные `game/<slug>/index.html` используют общий Approved-модуль.
- Опубликованная страница хранит идентичность и контент конкретной игры, но не собственную структуру страницы.
- Любое утверждённое изменение общего шаблона, layout, дизайна или подмодулей автоматически применяется ко всем опубликованным играм после продвижения Working → Approved.

### Working

- `game-page-working` — рабочая версия того же Game Page Module.
- Изменения структуры, дизайна, hero, media, ratings, sources, requirements, similarity и других подмодулей сначала выполняются и проверяются здесь.
- Работа в Working не должна менять production-страницы до утверждения.
- После прохождения автоматических и браузерных проверок Working продвигается в `main`; отдельной пересборки контента каждой игры для этого не требуется.

### Подмодули

Hero, Media, Ratings, Game Info, Reviews integration, Sources, Requirements, Similar games, News integration, Guides integration, Navigation, Layout и Game Page Design System являются подмодулями общего Game Page Module, а не независимыми реализациями страниц.

Перемещение или изменение подмодуля — например перенос карточки особенностей, изменение hero или новая сетка Media — считается обычным изменением Game Page Module. После утверждения оно применяется одинаково ко всем опубликованным страницам.

### Promotion gate

Перед продвижением Working → Approved новая версия обязана реально открыть в браузере репрезентативный набор уже опубликованных страниц, включая как минимум Spore, Fallout 2, The Witcher 3 и Elden Ring. Проверяется не только наличие файлов, а фактический рендер общей оболочки, отсутствие видимого runtime-failure и критических JavaScript errors.

Production deploy также повторяет эту браузерную проверку. Документационные изменения сами по себе не должны заново выкатывать пользовательский сайт.

## Freeze rule

Изменения создания/обогащения/рендера страницы игры, её source corpus, page-QC или Game Registry считаются изменениями стабильного модуля страницы.

Изменения генерации обзора и review-QC считаются изменениями review/editorial-подсистемы. Они могут читать и обогащать канонический source corpus через определённый контракт, но не должны заводить независимый конкурирующий источник истины.

Запрещено без отдельной задачи на изменение самого модуля страницы:

- отключать или обходить существующий pipeline создания страниц;
- заменять реальные факты/медиа заглушками или синтетическими данными;
- создавать второй независимый механизм страниц игр;
- создавать отдельный независимый review-source registry, расходящийся с `data/game-sources/<slug>.json`;
- делать наличие редакционного обзора обязательным техническим условием публикации страницы;
- скрывать найденные внешние материалы только потому, что обзор Игропоиска ещё не готов;
- ломать связи news / Popular / releases → Game Registry → game page;
- вводить game-specific шаблоны или стили вместо общей системы;
- менять Approved runtime напрямую в ходе незавершённой разработки вместо работы через Working;
- считать HTTP 200 достаточной проверкой работоспособности страницы без браузерного рендера.

## Правило для будущих PR

Если PR не посвящён непосредственно модулю страниц игр, изменения этого модуля должны быть минимальными и обратно совместимыми. Review/editorial-функции могут развиваться самостоятельно, но обязаны использовать каноническую игру и общий source corpus.

Этот документ является guardrail: **стабильный модуль страницы владеет базой данных об игре и полным корпусом её источников; редакционный обзор остаётся отдельным подключаемым материалом; опубликованные страницы используют только Approved-версию общего модуля.**
