# Production contract: новостной модуль

Этот документ фиксирует обязательные инварианты production-новостей Игропоиска. Любое изменение pipeline считается регрессией, если нарушает хотя бы один из пунктов ниже.

## 1. Автономность

- Канонический workflow: `.github/workflows/news-pipeline.yml`.
- Расписание хранится в `main` и запускается автоматически каждый час.
- Production-run работает с актуальным кодом `staging`, но не пишет новостные данные обратно в GitHub.
- Публикация выполняется атомарно в Yandex Object Storage через live manifest/snapshot.
- Ошибка отдельного источника не должна останавливать здоровую общую ленту.

## 2. Русская версия сайта

- На русской версии непереведённый английский заголовок не публикуется как fallback.
- Основной перевод EN→RU выполняется локальной моделью OPUS-MT (`Xenova/opus-mt-en-ru`) в GitHub Actions.
- Удалённые переводчики могут использоваться только как аварийный fallback, но английский исходник не может подменять русский результат.
- Если пригодный русский заголовок получить нельзя, конкретный материал пропускается; вся лента продолжает работу.

## 3. Изображения новостей

- Изображение — ускоряющий кэш, а не обязательная часть новости.
- Для свежих материалов изображение по возможности один раз копируется в Yandex Object Storage и публичная страница читает уже наш URL.
- Кэш изображений хранится 7 дней и затем может быть удалён housekeeping-процессом.
- Ошибка загрузки, кэширования, проверки или удаления изображения никогда не блокирует публикацию текста новости или всей ленты.
- Если изображения нет, оно просрочено или недоступно, UI показывает фирменную заглушку Игропоиска.
- Текст, дата, ссылка на источник, связь с игрой и архив новости не зависят от срока жизни изображения.

## 4. Publication gate

Блокировать публикацию разрешено только при угрозе целостности самой новостной ленты: сломанный обязательный JSON-контракт, пустая/катастрофически усечённая итоговая лента, невалидные даты/URL, нарушение русской локализации публичных карточек, блокирующая ошибка целостности игровых ссылок или невозможность сформировать пригодный snapshot.

Не являются самостоятельной причиной остановки всей публикации:

- временный 403/404/429/500 отдельного источника;
- низкая доля доступных официальных endpoints при наличии достаточного итогового контента;
- отсутствие или ошибка изображения;
- недоступность GitHub Models для необязательного semantic refinement;
- housekeeping/GC изображения.

Статус `degraded` публикуется и остаётся диагностическим. Только реальный `error` целостности может блокировать переключение live snapshot.

## 5. История и live-данные

- Текущая лента публикуется компактным snapshot в Yandex Object Storage.
- Полная история сохраняется через стабильные месячные архивы.
- Новый run сначала гидратирует предыдущую live-историю, затем строит новый snapshot.
- Удаление старых snapshot/media не должно удалять новостную историю.

## 6. Обязательные regression checks

При изменении news pipeline должны оставаться зелёными как минимум:

- `scripts/test-news-pipeline.mjs`;
- `scripts/test-news-pipeline-health.mjs`;
- `scripts/test-news-content-api.mjs`;
- `scripts/test-news-storage-content-api.mjs`;
- тесты retention/media fallback;
- `scripts/test-news-game-context-resolver.mjs`;
- `scripts/test-news-primary-game-refiner.mjs`;
- строгий аудит игровых хэштегов;
- production publication gate;
- реальный scheduled production-run после изменения критического pipeline-кода.

Документация сама по себе не считается защитой: эти правила должны быть отражены в автоматических тестах и workflow checks.

## 7. Production acceptance baseline

Базовый подтверждённый результат от 2026-08-26:

- scheduled run `32941655630` — success;
- следующий scheduled run `32945816176` — success;
- последний run собрал 38 русскоязычных industry items, 20 official items и 12 карточек главной;
- локальный перевод: 32 industry + 20 official, remote translation = 0;
- `source-language-fallback = 0`;
- publication gate passed;
- опубликован snapshot `20260826T080822Z-bc1ad8de9218-32945816176`;
- предыдущая live-история была успешно гидратирована следующим запуском;
- 1 ошибка кэширования изображения не остановила публикацию и ушла в fallback;
- storage cleanup отработал отдельно от публикационной целостности.

Этот baseline нужен как эталон поведения: последующие изменения не должны ухудшать автономность, локализацию, fail-soft поведение источников и изображений или атомарную публикацию.
