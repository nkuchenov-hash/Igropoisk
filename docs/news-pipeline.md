# Автономный новостной pipeline

## Назначение

Pipeline собирает новости, проверяет качество публикационного snapshot и автоматически публикует его в `main`. Интерфейс получает опубликованные данные только через `IgropoiskNewsContent`.

## Поток данных

```text
Глобальные игровые медиа ─┐
Региональные события ─────┼─> data/news.json ───────┐
Официальные источники ────┼─> data/publisher-news.json ─┼─> data/news-events.json
YouTube-сигналы ──────────┘   data/youtube-signals.json  └─> data/news-home-ru.json
                                                                  │
                                                                  ▼
                                                     IgropoiskNewsContent
                                                                  │
                                                     главная и архив новостей
```

## Cadence

Workflow запускается каждый час в `:23` UTC. Orchestrator читает `generatedAt` публикационных файлов и запускает только просроченные группы:

- `global-media` — один раз в 24 часа;
- `official-sources` — один раз в час.

Ручной запуск с `force=true` обновляет обе группы. Старые workflows сохранены только как ручные алиасы и не имеют собственного расписания.

## Атомарная публикация

Все сборщики работают в одном временном checkout GitHub Actions. После сбора заново строятся единый индекс событий и русский фид главной. Затем выполняются:

- `scripts/validate-news-pipeline.mjs`;
- `scripts/test-news-content-api.mjs`;
- `scripts/validate-news-module.mjs`;
- проверка целостности diff.

Только после успешных проверок JSON и изображения добавляются в один commit. Перед push commit ребейзится на актуальный `main` и проверяется повторно. При любой ошибке push не выполняется, поэтому production продолжает использовать предыдущий проверенный snapshot.

## Publication gate

Проверяются:

- обязательные JSON-файлы;
- минимальное количество записей;
- ровно 12 русских карточек главной;
- корректные URL и даты;
- наличие локальных изображений;
- отсутствие дублей URL;
- доля работающих официальных источников;
- защита от резкого обнуления или катастрофического сокращения ленты;
- регистрация всех источников в News Content API и manifest модуля.

Пороговые значения находятся в `config/news-pipeline.json`.

## Отчётность

Каждый запуск создаёт `tmp/news-pipeline-report.json` со статусом групп, командами, временем выполнения и ошибкой при её наличии. Workflow сохраняет отчёт как artifact на 14 дней. Отчёт не коммитится и не вызывает лишний production-деплой.

## Изменение pipeline

Новый источник добавляется в существующий сборщик или в новую группу `config/news-pipeline.json`. Он не должен читать или менять DOM, CSS, HTML либо код экранов. Новый output-путь необходимо явно добавить в `publication.commit_paths` и publication gate.
