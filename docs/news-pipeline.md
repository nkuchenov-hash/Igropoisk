# Автономный новостной pipeline

## Назначение

Pipeline собирает новости, проверяет качество публикационного snapshot и автоматически публикует его в `main`. Интерфейс получает опубликованные данные только через `IgropoiskNewsContent`.

## Поток данных

```text
Глобальные игровые медиа ─┐
Региональные события ─────┼─> data/news.json ───────────────┐
Официальные источники ────┼─> data/publisher-news.json ─────┼─> data/news-events.json
YouTube-сигналы ──────────┘   data/youtube-signals.json      └─> data/news-home-ru.json
                                       │                              │
                                       └──────────────┬───────────────┘
                                                      ▼
                                      data/news-pipeline-health.json
                                                      │
                              publication gate + read-only admin health
                                                      │
                                                      ▼
                                           IgropoiskNewsContent
                                                      │
                                         главная и архив новостей
```

## Cadence

Workflow запускается каждый час в `:23` UTC. Orchestrator читает `generatedAt` публикационных файлов и запускает только просроченные группы:

- `global-media` — один раз в 24 часа;
- `official-sources` — один раз в час.

Ручной запуск с `force=true` обновляет обе группы. Старые workflows сохранены только как ручные алиасы и не имеют собственного расписания.

Если health snapshot отсутствует или имеет статус `pending`, orchestrator принудительно инициализирует обе группы при следующем запуске.

## Атомарная публикация

Все сборщики работают в одном временном checkout GitHub Actions. После сбора заново строятся единый индекс событий, русский фид главной и health snapshot. Затем выполняются:

- `scripts/validate-news-pipeline.mjs`;
- `scripts/test-news-pipeline-health.mjs`;
- `scripts/test-news-content-api.mjs`;
- `scripts/validate-news-module.mjs`;
- проверка целостности diff.

Только после успешных проверок JSON, health snapshot и изображения добавляются в один commit. Перед push commit ребейзится на актуальный `main` и проверяется повторно. При любой ошибке push не выполняется, поэтому production продолжает использовать предыдущий проверенный snapshot.

## Publication gate

Проверяются:

- обязательные JSON-файлы;
- минимальное количество записей;
- ровно 12 русских карточек главной;
- корректные URL и даты;
- наличие локальных изображений;
- отсутствие дублей URL;
- доля работающих официальных источников;
- внутреннее соответствие health snapshot публикационным JSON;
- возраст каждого набора данных относительно warning и blocking thresholds;
- последовательные ошибки официальных источников;
- защита от резкого обнуления или катастрофического сокращения ленты;
- регистрация всех источников в News Content API и manifest модуля.

Пороговые значения находятся в `config/news-pipeline.json`. Статус `degraded` сохраняет публикацию и показывает предупреждение. Статус `error` блокирует commit.

## Health snapshot

`data/news-pipeline-health.json` содержит:

- последнее время успешной подготовки snapshot;
- проверенные группы источников;
- количество и возраст каждого JSON-набора;
- число используемых и отсутствующих изображений;
- долю успешных официальных источников;
- текущие ошибки;
- историю последовательных ошибок и список persistent failures;
- применённые thresholds, предупреждения и блокирующие ошибки.

Успешный ответ источника сбрасывает его счётчик ошибок. Источник попадает в persistent failures после трёх последовательных ошибок, если конфигурацией не задан другой порог.

## Read-only админка

`admin/news-health/` показывает health snapshot пользователю с ролью `admin`. Экран не содержит форм изменения данных, не запускает workflow и не отправляет запросы записи. Его единственные внешние действия — открыть JSON и журнал GitHub Actions.

## Production smoke

После каждого успешного GitHub Pages deploy отдельный job открывает фактически опубликованный URL и проверяет:

- главную и архив новостей;
- карточки, поиск и управление лентой;
- отсутствие legacy news runtime;
- доступность и корректный статус health snapshot;
- наличие read-only страницы `admin/news-health/`.

Ошибка smoke не переписывает данные, но делает production workflow неуспешным и видимым в GitHub Actions.

## Отчётность

Каждый запуск создаёт `tmp/news-pipeline-report.json` со статусом групп, командами, временем выполнения, сводкой health и ошибкой при её наличии. Workflow сохраняет отчёт и health snapshot как artifact на 14 дней. Отчёт не коммитится и не вызывает лишний production-деплой.

## Изменение pipeline

Новый источник добавляется в существующий сборщик или в новую группу `config/news-pipeline.json`. Он не должен читать или менять DOM, CSS, HTML либо код экранов. Новый output-путь необходимо явно добавить в `publication.commit_paths` и publication gate.
