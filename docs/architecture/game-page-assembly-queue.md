# Очередь сборки страниц игр

## Назначение

Новостной модуль и модуль сборки страниц игр работают независимо.

Если новостной модуль подтверждает, что новость относится к реальной игре, но страницы этой игры ещё нет в production, он **не создаёт страницу сам**. Он только кладёт подтверждённую заявку во временную очередь в Yandex Object Storage.

После этого новость публикуется обычным способом и не ждёт создания страницы.

## Обязательный поток

```text
Новость
  ↓
проверка личности игры
  ↓
страница уже есть? ── да ──> можно использовать ссылку на страницу
  │
  нет
  ↓
временная очередь Object Storage
  ↓                         одновременно
модуль сборки страниц       новость публикуется сразу
  ↓
полный обычный цикл страницы
  ↓
production-страница реально существует
  ↓
заявка удаляется из временной очереди
  ↓
следующие новости могут использовать ссылку на страницу
```

## Жёсткие правила

1. Новостной pipeline не создаёт, не собирает и не выкладывает игровые страницы.
2. Единственная передача новой игры из новостей в систему страниц — запись в `queues/game-page-assembly/pending/` в Object Storage.
3. В очередь попадают только игры с подтверждённой канонической личностью и каноническим `game_id`.
4. Одна игра хранится как одна идемпотентная запись `<game_id>.json`; повторные новости дополняют ту же заявку.
5. Ошибка временного хранилища не имеет права блокировать публикацию новостей.
6. Пока production-страницы нет, публичная новость не должна содержать несуществующую ссылку на эту страницу.
7. Очередь читает только обычный модуль жизненного цикла/сборки страниц. Он применяет к игре тот же полный процесс, что и к любому другому источнику появления игры: сбор данных, редактуру, медиа, проверки качества и публикационный gate.
8. Сам факт появления игры в новостях не ослабляет требования к качеству страницы.
9. Заявка остаётся во временном хранилище при неудачной или незавершённой сборке и может быть обработана следующим запуском.
10. Заявка удаляется только после подтверждения, что `game/<slug>/index.html` и соответствующий production draft реально находятся в `main`.

## Разделение ответственности

### Новостной модуль

Отвечает за:
- обнаружение события;
- проверку, что упомянута именно игра;
- сопоставление с существующей страницей;
- помещение отсутствующей игры в очередь;
- публикацию новости независимо от страницы.

Не отвечает за:
- сборку страницы;
- наполнение страницы;
- обзор;
- Game DNA;
- подбор похожих игр;
- медиа страницы;
- выкладку страницы.

### Модуль сборки страниц

Отвечает за:
- получение заявок из временной очереди;
- включение их в собственный приоритетный план;
- полный обычный цикл сборки;
- сохранение незавершённой работы;
- публикацию только после собственных проверок;
- удаление выполненной заявки из временного хранилища после фактического появления production-страницы.

## Защита от регрессий

`scripts/test-game-page-assembly-queue.mjs` должен гарантировать, что:
- news workflow пишет в очередь;
- news workflow не запускает отдельный fast page creator;
- ошибка записи в очередь не блокирует новости;
- lifecycle workflow читает и подтверждает очередь;
- названия вроде `Super Smash Bros. Ultimate` не превращаются в `edition` только из-за слова `Ultimate`; изданием считается явная форма вроде `Ultimate Edition`.
