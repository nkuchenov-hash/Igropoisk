# Фаза A — стабилизация публикации

## Цель

Публикация сайта не должна исправлять, дописывать или перестраивать исходный код. GitHub Pages получает только заранее проверенный снимок репозитория.

## Зафиксированный production

Рабочая версия перед миграцией сохранена в ветке `production-stable-2026-08-04`. Она является точкой аварийного возврата и не используется для разработки.

## Изолированная разработка

Все изменения фазы A выполняются в ветке `phase-a-stabilization`. До завершения проверок ветка `main` и опубликованный сайт не изменяются.

## Новая модель публикации

1. Проверяется, что все ранее внедрявшиеся во время деплоя изменения уже находятся в исходных файлах.
2. Проверяется синтаксис JavaScript и Python.
3. Проверяется JSON-контент.
4. Проверяются publish gate страниц игр и редакционного конвейера.
5. Проверяется единый контракт ширины.
6. Только после успешного прохождения всех проверок новый job получает свежий checkout того же commit и публикует его без `sed`, `--write` и других модификаций.

## Запрещено в production-деплое

- изменять HTML, CSS или JavaScript;
- внедрять временные исправления;
- переписывать авторизацию;
- запускать генераторы с записью в рабочие файлы;
- проверять наличие отдельных исторических commit;
- публиковать снимок, отличный от проверенного commit.

## Откат

Пока новая схема не опубликована, production продолжает работать по старой ветке `main`. После публикации аварийный возврат выполняется к сохранённой стабильной версии либо к последнему успешному production commit.

## Критерий завершения фазы A

- stability gate проходит полностью;
- точный staging-артефакт создаётся без изменения исходных файлов;
- production workflow не содержит самоизменяющихся шагов;
- текущий внешний вид и контент не изменены намеренно;
- изменение контента не может обойти проверки и повредить опубликованный сайт.
