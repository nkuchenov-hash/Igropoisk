# Игропоиск — Game Page Editorial Skills v1

**Статус:** READY FOR MODEL BENCHMARK  
**Зафиксировано:** 2026-09-04

## Зачем три skill, а не один prompt

Subtitle, Description и Features выполняют разные редакционные задачи. Они используют одну и ту же доказательную базу, но требуют разного отбора материала, разной степени сжатия и разных критериев качества.

Поэтому production-контракт состоит из трёх независимых skills:

- `config/parsers/game-page-subtitle-skill.json`
- `config/parsers/game-page-description-skill.json`
- `config/parsers/game-page-features-skill.json`

У каждого skill после benchmark будет собственная утверждённая модель. Одна модель может победить в нескольких skills, но это не предполагается заранее.

## Общий источник истины

Все три skills используют только канонический корпус Game Page Module:

- `data/game-sources/<slug>.json` — список и метаданные источников;
- `data/game-source-content/<slug>.json` — сохранённый readable-текст источников;
- Game Registry / `game_id` — точная идентичность игры.

Skills не ищут источники самостоятельно, не создают параллельный source registry и не используют модельную память вместо корпуса.

**Важно:** benchmark и production не имеют права повторять старую схему с `N` источниками и `N` символами от каждого источника. Если весь корпус не помещается в один context window, он обрабатывается по детерминированным чанкам с полным покрытием, а не отбрасывается.

## Skill 1 — Subtitle

### Задача

Дать короткий узнаваемый портрет игры.

Subtitle — это не жанровая подпись и не мини-описание. Он должен передать минимальный набор главных признаков, после которых возникает правильный образ именно этой игры.

### Принцип

Не существует обязательной формулы `сеттинг + враг + механика`. Для каждой игры выбираются те признаки, которые реально несут её идентичность.

Примеры:

- Spore достаточно формулы `От клетки до космической цивилизации`: она уже почти полностью задаёт уникальный образ игры.
- Dangerous Dave нельзя свести только к отдаче дробовика: без особняка, нежити/монстров образ игры заметно искажается.
- Far Cry нельзя свести только к открытым тропическим перестрелкам: наёмники, эксперименты/мутанты и свобода подхода вместе точнее описывают характер игры.

### Формат

Обычно 7–15 слов, мягкий максимум 18. Одна строка. Не обязана быть полным предложением.

### Главный тест

После удаления названия игры subtitle должен оставаться узнаваемым портретом, а не подходить десяткам других игр.

## Skill 2 — Description

### Задача

Дать полноценное вводное описание игры: что это, кем является игрок, что он делает и какие системы определяют опыт.

### Формат

Ориентир 130–190 русских слов, мягкий максимум 220. Один–три нормальных абзаца, без bullets.

### Обязательная содержательная проверка

Описание должно отвечать как минимум на четыре вопроса:

1. Что происходит / какова исходная ситуация?
2. Кто игрок и чего он добивается?
3. Что игрок регулярно делает?
4. Какие конкретные системы или детали отличают эту игру от обычного представителя жанра?

Это не рецензия: Description не ставит оценку, не выносит вердикт и не обязан обсуждать достоинства/недостатки.

## Skill 3 — Features

### Задача

Дать быстрый сканируемый список характерных особенностей игры.

### Формат

4–6 пунктов. Обычно 2–7 слов на пункт, мягкий максимум 10. Не полноценные предложения. Без точки в конце.

Хорошо:

- `Дробовик с физической отдачей`
- `Полиция и дорожные правила`
- `Выборы Paragon и Renegade`
- `Пять стадий развития`

Плохо:

- `Захватывающий сюжет`
- `Красивая графика`
- длинное предложение, объясняющее целую механику вместо тезиса.

Features — не список рекламных преимуществ. Допустимы нейтральные, странные или даже неудобные особенности, если именно они помогают понять характер игры.

## Общие правила качества

Для всех трёх skills:

- точная версия игры обязательна;
- факты только из канонического корпуса;
- механики описываются в настоящем времени;
- evergreen-подача;
- никаких `по данным источников`, `корпус показывает`, `модель обнаружила`;
- никаких выдуманных деталей ради выразительности;
- конкретика важнее общих прилагательных;
- source corpus определяет факты, но не диктует риторическую структуру;
- техническая ошибка утверждённой модели вызывает retry той же модели, а не тихую замену другой моделью.

## Связь с Review Skill

Review Skill — четвёртая отдельная редакционная задача. Он читает тот же канонический корпус, но имеет собственный workflow, модель, QC и жизненный цикл.

Страница игры не должна ждать готовности Review Skill.
