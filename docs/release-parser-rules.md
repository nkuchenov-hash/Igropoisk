# Парсер календаря релизов

## Назначение

Парсер поддерживает публичный календарь выхода игр и внутреннюю редакционную очередь. Он обнаруживает новые релизы, фиксирует переносы, сохраняет источники и создаёт черновики страниц игр. Автоматическая публикация страниц запрещена.

## Приоритет источников

1. Официальный сайт разработчика или издателя — `100`.
2. Официальный магазин платформы — `90`.
3. IGDB — `80`.
4. RAWG — `55`, только резервное обнаружение и дополнение метаданных.
5. Игровые СМИ и сторонние календари — `30`, только обнаружение. Найденная там дата должна быть подтверждена первичным источником.

Значение из источника с более высоким приоритетом является основным. Конфликт двух официальных источников не разрешается автоматически и получает статус `needs_review`.

## Правила даты

Дата хранится как отдельное событие `ReleaseEvent`, а не как одно поле игры. У одной игры могут быть разные события для платформ, регионов, раннего доступа, версии 1.0, порта, ремастера или дополнения.

Допустимая точность:

- `exact` — известен точный день;
- `month` — известен только месяц;
- `quarter` — известен квартал;
- `year` — известен только год;
- `tbd` — дата не объявлена.

Парсер не подставляет фиктивный день для месяца, квартала, года или `Coming Soon`. Для диапазона отдельно сохраняются `date_start` и `date_end`.

Каждое изменение сохраняет старое и новое значение. Если новая дата позже старой, создаётся событие `delayed`. Замена точной даты на период или `TBD` также считается важным изменением.

## Объединение и дубли

Основные идентификаторы:

- Steam AppID;
- IGDB ID;
- RAWG ID;
- идентификаторы PlayStation, Xbox, Nintendo, Epic и GOG при их наличии.

При отсутствии идентификатора используются нормализованное название, альтернативные названия, разработчик, платформа, дата и хеш изображения. Совпадение только по названию недостаточно.

Полные версии, ранний доступ, DLC, ремастеры и порты не сливаются в одну запись без явной связи.

## Изображения

Порядок выбора:

1. официальный press kit или сайт издателя;
2. официальная вертикальная обложка магазина;
3. IGDB cover;
4. RAWG как резерв;
5. ручная загрузка редактором.

Запрещены:

- изображения из статей игровых СМИ;
- водяные знаки;
- фан-арт;
- случайные результаты поиска картинок;
- рекламные коллажи;
- сгенерированные ИИ замены официальной обложки.

Предпочтительный размер вертикальной обложки — `600 × 900`. Файл должен иметь разрешённый MIME-тип и размер не менее `15 000` байт. Для скачанного файла сохраняются MIME, размер и SHA-256. При ошибке скачивания разрешён временный показ проверенного официального URL, но запись получает соответствующий статус.

Изображения сторонних СМИ не хотлинкуются. Локальное кэширование выполняется только для официальных материалов и источников, условия которых допускают такое использование.

## Редакционная защита

Для каждого черновика хранится владелец поля:

- `parser` — поле может обновляться автоматически;
- `editor` — редактор заполнил поле вручную;
- `editor_locked` — парсер не имеет права менять поле.

Парсер сохраняет `locked_fields` из предыдущего черновика. Он не удаляет ручной текст, выбранную редактором обложку, заголовок или подтверждённую вручную дату.

Статусы очереди:

`discovered → needs_review → draft → ready → published`

Парсер может создавать `discovered`, `needs_review` и `draft`. Перевод в `ready` и `published` выполняется редактором.

## Минимум для черновика страницы

- название;
- одно событие релиза или честный статус `tbd`;
- платформа;
- хотя бы один источник;
- официальная обложка либо фирменная заглушка.

Длинное описание, редакционный текст, итоговая структура страницы и публикация автоматически не создаются.

## Расписание

- основной сборщик запускается каждые 6 часов;
- ближайшие 90 дней полностью сверяются при каждом запуске;
- записи без точной даты сохраняются и перепроверяются;
- общий GitHub Actions-планировщик запускается ежечасно и выполняет только парсеры, у которых наступил интервал;
- ошибки одного источника не удаляют предыдущие подтверждённые данные.

## Выходные файлы

- `data/releases/current.json` — текущий календарь;
- `data/releases/changes.json` — история обнаруженных изменений;
- `data/parser-runs/releases.json` — журнал последнего запуска;
- `data/release-drafts/*.json` — черновики страниц;
- `assets/covers/releases/*` — проверенные локальные копии официальных обложек.
